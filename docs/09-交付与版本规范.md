# 09 · 交付与版本规范

> 这一篇规定「一个版本怎么算交付完成」，以及**交付后必须输出什么**。
> 任何一次对外可见的改动，都必须走完这里的流程，不允许只改代码不说话。

## 1. 版本号规则

`build.gradle` 的 `version` 是唯一事实来源，jar 内 `META-INF/mods.toml` 的 `version` 由它替换。

| 变更性质 | 版本位 | 例子 |
|---|---|---|
| 只修 bug / 兼容已有模组版本 / 调整默认值 | 补丁位 | 4.5.1 → **4.5.2** |
| 新增功能、新增配置项、新增命令或工具 | 次版本位 | 4.5.x → **4.6.0** |
| 破坏性改动（删配置键、改网络协议不兼容、换适配基准版本） | 主版本位 | 4.x → **5.0** |

同时要检查：

- `config/ModConfig` 里有没有删过键（删键 = 破坏性，需在更新日志写明「该项已移除」）；
- `network/*Network` 的 `PROTOCOL` 是否升过（不升会导致旧客户端连新服务端出错甚至踢人）；
- `src/main/resources/META-INF/mods.toml` 的依赖区间是否仍然成立。

## 2. 更新日志的写法

**位置：仓库根 `CHANGELOG.md` 顶部**（最新版本在最前）。
`CHANGELOG_4.x.md` 这类单文件是历史遗留副本，**不要**再新增。

固定结构（照抄，不要自创标题层级）：

```markdown
## 4.5.2 — 2026-10-23

> 一句话说明这个版本的性质：补丁 / 功能 / 破坏性，以及它最想解决的问题。

- 新增 xxx：一句话说清能力边界与前置条件（需要装什么、默认开还是关）。
- 修复 xxx：写清「修复前的表现」和「修复后的行为」，不要只写“修了个 bug”。
- 兼容 xxx：写明适配到哪个版本、哪些注入点重新核对过。
- 配置：新增 `a.b`（默认 `false`，范围 x–y）、`a.c`（默认 `0.5`）。
- 已知限制：本项目结构上做不到的事，一句话交代。
- 版本号、构建产物统一为 `4.5.2`。

构建产物：`build/libs/Verity扩展增强-4.5.2.jar`

SHA-256：

```text
<小写 64 位>
```
```

硬性要求：

1. **每个版本必须有条目**，哪怕是「只改了日志」也要写；
2. 条目按「新增 / 修复 / 兼容 / 配置 / 限制」归类，同一类合并写，不要逐文件罗列；
3. 面向玩家的版本额外写「升级提示」（要不要删配置、要不要重装依赖）；
4. 产物名与哈希必须与本版本实际 jar 一致，**不许沿用上一版**；
5. 写「为什么」而不是「改了什么文件」——接手的人靠这段理解设计意图。

## 3. 交付流程（缺一步就不算交付）

```text
1. 改代码
2. ./gradlew compileJava                       # 编译通过
3. 跑对口的自检任务（改配置/云端/mixin 时必跑）
4. 升 build.gradle 的 version
5. 写 CHANGELOG.md 条目（含占位哈希）
6. ./gradlew clean productionJar               # 构建
7. 计算 SHA-256，回填 CHANGELOG 与 release/SHA256.txt
8. 部署：删旧 jar → 放新 jar（同 modId 只能一个）
9. 实机启动一次，确认日志无降级/异常
10. 输出「交付状态报告」（见第 4 节）
```

部署位置：

| 平台 | 路径 |
|---|---|
| PC（PCL2） | `D:\pcl2\.minecraft\versions\1.20.1-Forge_47.4.21=\mods\` |
| Android（FCL） | `/storage/emulated/0/FCL/.minecraft/versions/1.20.1/mods/` |

计算哈希：

```powershell
(Get-FileHash -LiteralPath "build\libs\Verity扩展增强-4.5.2.jar" -Algorithm SHA256).Hash
```

## 4. 交付后必须输出的「项目状态报告」

每次交付，在回复末尾**原样输出**下面这块（字段不能省，没有的写「无」）：

```markdown
## 交付：v<版本>（<YYYY-MM-DD>）

**产物**
- 文件：`build/libs/Verity扩展增强-<版本>.jar`（已部署到 `<路径>`）
- SHA-256：`<64 位小写>`
- 构建：`./gradlew clean productionJar` 通过

**本版改动**
- 新增：……
- 修复：……
- 兼容：……

**配置变更**
- 新增键：`section.key`（默认 `x`，说明）
- 变更键：`section.key` 默认值 a → b
- 移除键：无

**兼容性**
- 适配基准：Verity JE `6.0.0`；注入点/反射成员核对结果：通过 / 有 N 处待适配
- 网络协议：是否变更（`verity_hold` 1 → 1）
- 依赖区间：Forge `[47.3,48)`（编译基准 47.3.0）、GeckoLib `[4.4,)`

**已知问题**
- ……

**验证方式**
- 命令：`/……`
- 日志关键行：`……`
```

要点：

- **SHA-256 必须与部署文件一致**，不能凭记忆填；
- 「本版改动」要与 `CHANGELOG.md` 条目一致（可以更短，但不能多出没写进 CHANGELOG 的东西）；
- 「已知问题」要写真实存在但本版不打算修的（结构性限制见 `docs/08`），不要写「暂无」来糊过去；
- 「验证方式」给的是**别人能照着重现**的步骤，而不是“我测过了”。

## 5. 交付包内容规范

对外的 AI 接手包（本目录）必须包含：

```text
AGENTS.md            交付与约束入口
README.md            人类可读说明
CHANGELOG.md         全部版本变更（顶部为最新）
docs/01..09          架构 / 目录 / mixin / 配置 / 网络 / 构建 / 扩展 / 限制 / 交付
src/main/java        真实源码（不含反编译参考目录）
src/main/resources   本模组资源（不含原版资源副本）
src/test/java        自检类
lib/                 编译期依赖说明（不随包分发第三方 jar，geckolib 除外）
tools/               准备依赖的脚本
release/             当版 jar + SHA256.txt
```

发布 zip 时**不要**包含：`build/`、`.gradle/`、`run/`、`logs/`、任何 `.toml.bak/.snapshot/.broken`、
以及 `src/main/java/**` 下的历史 jar / 反编译目录 / 日志 / 对话导出 JSON。

## 6. 版本状态如何对外描述（给玩家的一句话）

除技术报告外，交付时附一句人话摘要，格式：

```text
v4.5.2：新增星之遥控器适配与说话 Q 弹；修复配置文件被写坏导致启动崩溃、云端开关被读回关闭；
云端下发的配置不再盖掉你本地改过的项。直接替换 jar 即可。
```

三句话结构：**这版加了什么 / 修了什么 / 用户要做什么**。不要贴代码、不要贴日志。
