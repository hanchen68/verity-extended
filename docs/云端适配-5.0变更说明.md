# Verity 扩展增强 5.0 · 云端适配变更说明

> **读者**：云端后端 / 运维 / 客服
> **对应 Mod 版本**：5.0
> **上一份云端文档**：`docs/云端适配总览.md`（4.4 时代，**其中配置下发章节已作废**，见 §2）
> **写于**：2026-10-25

---

## 0. 一句话结论

**5.0 对云端最大的变化是「收权」：`overrides` 从「全量 180 项可下发」收窄成「只允许 21 项 API 连接配置」。**

除此之外，接口路径、鉴权、响应信封、资源中心、备份接口**全部没变**。
云端侧真正需要动手的只有两件事：

1. **清掉 `overrides` 里除那 21 项之外的一切键**（否则会被客户端静默丢弃并打日志）；
2. **不要再指望用 `overrides` 关功能** —— 功能开关现在一律由本机玩家控制。

---

## 1. 5.0 变更清单（云端视角）

| 变更 | 影响云端 | 严重度 |
|---|---|---|
| `overrides` 改为**白名单制**，只接受 21 项 | 云端下发的功能开关/行为参数全部失效 | 🔴 **高** |
| `overrides` 白名单键**跳过**「本地非默认值就保留」规则 | 云端终于能真正改动上游地址/密钥/模型 | 🟡 中（是修复不是破坏） |
| 配置项总数 **187**（4.4 是 181） | 若云端维护了键清单，需重新对齐 | 🟡 中 |
| **插件系统整体删除**（3 个配置键消失） | 若下发过 `plugin.*` 会变成「未知配置项」 | 🟢 低（本来就不允许下发） |
| 新增 `verity_wander.enabled`、`verity_help.enabled` | 仅本地生效，云端**不能**下发 | 🟢 低 |
| 适配原版 Verity **6.0.0** | 无云端影响 | — |
| 新增指令 `/verity-context clear\|restore\|status` | 无云端影响（本地上下文管理） | — |
| 对话历史 tool_calls 配对自动修复 | 无云端影响（**但会减少 400，上游侧错误率下降**） | ✅ 利好 |

### 1.1 关于「白名单制」——为什么必须收权

4.4 时代 `overrides` 是 180 项全量可下发。线上真实故障：

> 玩家在配置界面把某个开关关掉 → 下一次云端拉取又把它开回来 → 玩家看到「我的设置自己变回去了」。
> `cloud.enable` 反复自动关闭也是这条链路上的误诊产物之一。

根因是**云端下发值被写穿进了 ForgeConfigSpec**（不是包一层 getter），
所以云端下发过的键，玩家本地怎么改都会被下一轮拉取覆盖。

5.0 的定论：**真正适合云端统一管理的只有「怎么连上去」**——换上游地址、换密钥、换模型。
这些玩家自己配容易配错，也确实是运营方该管的。
功能开关、行为参数、数值调优一律交回本机。

## 3. 允许云端下发的 21 项（唯一权威清单）

键名**全名精确匹配**，少一个字都不行。分组仅为便于阅读。

### 3.1 对话模型连接（5 项）

```
llm.apiProvider          // 协议格式：openai / ollama / ...
llm.apiUrl               // 上游地址
llm.apiKey               // 密钥
llm.model                // 模型名
llm.requestTimeout       // 请求超时（秒）
```

### 3.2 语音识别连接（7 项）

```
speech_recognition.apiProvider
speech_recognition.apiUrl
speech_recognition.apiKey
speech_recognition.model
speech_recognition.requestFormat    // 请求体格式
speech_recognition.authType         // 鉴权方式：bearer / header / query ...
speech_recognition.responseField    // 从哪个字段取识别文本
```

### 3.3 语音合成连接（5 项）

```
text_to_speech.apiProvider
text_to_speech.apiUrl
text_to_speech.apiKey
text_to_speech.apiModel
text_to_speech.apiVoice
```

### 3.4 线路与翻译（4 项）

```
tts_route.kind                      // 朗读走哪条路：native / local / endpoint
voice_language.translateModel       // 台词翻译模型
voice_language.translateUrl         // 翻译接口地址
voice_language.translateApiKey      // 翻译密钥
```

### 3.5 白名单的三条硬规则

1. **只允许上面 21 项**。其余键一律丢弃，日志会写明原因：
   - 普通键：`不在白名单，已忽略`
   - `cloud.*`：`cloud 段禁止下发`
   - `ai_extensions.webSearch*`：`联网搜索由本机管理`（这组是历史例外，理由单独记录）
2. 🔴 **白名单键不做「本地优先」保护**。
   4.4 的规则是「首次接管时，如果本地不是默认值就保留本地」——
   这条对白名单键**必须跳过**，否则云端永远改不动已经配过的上游地址
   （玩家配过一次自定义 API，云端之后再也推不下去）。
3. **白名单里没有任何布尔键**。若云端需要关某个功能，只能靠「不下发」或让玩家自己在游戏里关。

## 4. 配置下发接口（路径未变，语义有变）

### 4.1 请求

```http
POST /api/v1/getconfig
Authorization: Bearer <api-key>
Content-Type: application/json
```

```json
{
  "mod_version": "5.0",
  "client_id": "...",
  "billing_protocol_version": 2
}
```

`mod_version` 现在会传 `5.0`。**云端不要按版本号拒服务**，4.x 与 5.0 用的是同一套协议。

### 4.2 响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "version": 13,
    "config_id": "cfg_xxx",
    "overrides": {
      "llm.apiUrl": "https://upstream.example/v1",
      "llm.model": "deepseek-chat",
      "llm.requestTimeout": 45
    }
  }
}
```

- `data.version` 仍必须是 `>= 0` 的整数、每次改动递增；**回滚版本仍会被整份忽略**（这条没变）。
- `data.overrides` 为空对象或缺失 = 「本次没有覆盖」，客户端会**清空所有现有覆盖**并还原成本地值。
  所以「临时禁用某个下发」的正确做法是**从 overrides 里删掉那个键**，不要下发 `null`。
- `overrides` 支持两种写法，同时出现时**点分写法优先**：

```json
{
  "llm.apiUrl": "https://flat.example/v1",
  "llm": { "apiUrl": "https://nested.example/v1" }
}
```

### 4.3 类型转换

按**配置项声明类型**转换，不是按 JSON 字面类型：

| 声明类型 | 云端可给 | 转换行为 |
|---|---|---|
| 整数 | `"20"` / `21.6` | 字符串解析；小数四舍五入（21.6 → 22） |
| 字符串 | `123` | 转成 `"123"` |
| 字符串 | `{"a":1}` | ❌ 丢弃，保留原值 |

超范围的值（如 `llm.requestTimeout` 声明 5~300，给 1）**整项丢弃**，不会写进去。
边界值（300）会被接受。

> 注：布尔转换代码仍然存在，但 5.0 白名单里已没有布尔键，所以这条路径当前不可达。

## 5. 云端上线动作清单

按顺序做，每步都能独立验证。

### 5.1 必做：清理现有 overrides

在云端后台/数据库里检查所有已配置的 `overrides`：

- [ ] 保留 §3 的 21 个键，**其余全部删除**
- [ ] 特别检查有没有下发过这些（这些是线上实际出现过的误配）：
  - `hud.*`（界面开关）
  - `ai_extensions.memoryEnabled` 等功能开关
  - `plugin.*`（插件系统已整体删除）
  - `gameplay_safety.*`
  - `verity_wander.*` / `verity_help.*`（新增项，不可下发）
- [ ] 确认 `cloud.*` 从未出现在 overrides 里（这段是硬禁止，会出现「引导过程被交出去」的风险）

> 客户端会丢弃非法键并打 INFO 日志，不影响玩家使用；但**云端会误以为策略生效了**，
> 这才是真正的风险 —— 排查时看客户端日志 `cloud/CloudOverrides` 那几行能直接看到被丢弃的键名。

### 5.2 必做：确认「白名单键能真正推下去」

以前因为「本地优先」规则，云端改不动已配置过的地址。5.0 修了，验证方式：

1. 让测试账号在游戏里手填一个自定义 `llm.apiUrl`；
2. 云端下发另一个 `llm.apiUrl`；
3. 重进游戏 → 配置界面应显示**云端那个地址**（不是玩家填的）。

若显示的还是玩家填的，说明客户端不是 5.0，或该键写错了名字。

### 5.3 检查：配置项计数

- [ ] 若云端维护了 187 项的键清单，确认与 `docs/Mod配置云端下发适配文档.md` 对齐
- [ ] 删除清单里的 `plugin.enabled` / `plugin.maxLoaded` / `plugin.allowBlockEdit`（3 项，已随插件系统删除）
- [ ] 新增 `verity_wander.enabled` / `verity_help.enabled`（仅作记录，不可下发）

### 5.4 无需改动

以下是 4.4 已经定好、5.0 完全没有变化的，不用碰：

- 鉴权方式（`Authorization: Bearer`）
- 响应信封（`code` / `message` / `data`）
- 状态码语义（401 / 403 / 404 / 413 / 429 / 5xx）
- 资源中心三个列表接口：`GET /api/v1/skins`、`GET /api/v1/mimo/voices`、`GET /api/v1/mmd/projects`
- 资源下载的同源限制、大小上限、SHA-256 校验
- 备份接口：`POST /api/v1/user/data/backup`、`GET /api/v1/user/data/backup/latest`
- 计费协议（`billing.*` / `pricing.*`）
- 配对码兑换：`POST /api/v1/exchange/exchange`（**长度必须正好 6 位**）

## 6. 顺带说明：两个可能被误认为「云端功能」的东西

### 6.1 内置线路（`data.builtin_api`）

这条**不是 overrides**，是响应里的具名字段，独立于白名单，照旧可用。
它下发 `chatTier` / `sttTier` / `ttsTier` / `chatRouteId` 等，配合 `routePolicy` 选择内置线路。

🔴 **密钥按设计不落盘**：客户端快照里不含内置线路密钥。若快照里没有密钥、
且重新同步尚未成功，客户端会提示：

> 云端快照不含内置线路密钥（按设计不落盘），内置对话在重新同步成功前不可用

这是预期行为，不是故障。云端不要为了「消除这条提示」而把密钥写进可落盘的位置。

### 6.2 `/verity-context clear`

5.0 新增的本地指令，用来在对话历史被污染时清空上下文。**纯本地行为**，
不发任何请求给云端，云端不需要感知。

（顺带：5.0 会自动修复对话历史里 tool_calls 与 tool 回复的配对，
上游那边「insufficient tool messages following tool_calls」这类 400 会明显减少。）

## 附录 A：客户端侧的实现约束（供云端理解，不需动作）

- **写穿机制**：云端值直接写进 `ForgeConfigSpec`，因为项目里有 500+ 处直接读 `ModConfig.XXX.get()`，
  只在 getter 上包一层的话那些地方会静默拿到本地值，覆盖会「看起来生效、实际一半没变」。
- **保存守卫**：写穿有代价 —— 任何一次 `COMMON_SPEC.save()` 都会把云端值写进玩家的 TOML 文件。
  所以所有保存都必须走 `CloudOverrides.saveCommon()` / `saveClient()`：
  保存前把被覆盖的键临时写回本地值，保存后写回覆盖值。
  源码级自检会拦住任何裸的 `COMMON_SPEC.save()`。
- **本地改动优先于云端**：两次拉取之间玩家自己改了某个值（配置界面、管理员指令、直接编辑 TOML 后重载都算），
  会采纳为新的本地值并放弃该项覆盖；**云端把这个键改成新值时才重新接管**。
- **60 秒去重窗口**：同版本配置 60 秒内重复下发只应用一次。窗口内有「内存里是否还有配置」的判据，
  配置被清空时不会误判成重复。

这四条是客户端的内部实现，云端只需知道结论：**下发要幂等、改值才重新接管、别指望下发功能开关。**
