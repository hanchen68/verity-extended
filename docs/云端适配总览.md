# Verity 扩展增强 · 云端适配总览

> 适用 Mod 版本：4.4+
> 读者：云端后端 / 运维
> 目标：把扩展用到的全部云端接口、鉴权、响应格式、限制和上线顺序集中到一处。
> 详细字段级说明见文末的专项文档。

## 1. 云端承担的功能

扩展的云端能力分四块：

1. **配置下发**：登录后拉取账号配置、线路、计费参数和 `overrides`。
2. **资源中心**：皮肤、MiMo 音色、MMD 项目列表与下载。
3. **对话/日记备份**：一键上传当前对话与日记，或恢复最近一次备份。
4. **计费/用量**：付费线路的预留、结算、上报（沿用既有协议，不在本次新增范围）。

所有请求都走同一个 Base URL，默认：

```text
https://verity.xrstudio.cn/api/v1/
```

本机回环地址允许 HTTP，其余必须 HTTPS。

## 2. 统一约定

### 2.1 鉴权

除登录/配对流程外，所有接口都带：

```http
Authorization: Bearer <api-key>
Accept: application/json
```

`api-key` 由云端配发，客户端保存在 `config/verity_extended/cloud-credentials.json`，不会写进日志或导出文件。

### 2.2 响应信封

统一使用：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- HTTP `200` 且 `code == 0` 才算成功。
- `code != 0` 时，`message` 会直接显示给玩家，请写可读中文。
- 列表接口的数组放在 `data` 下，具体字段见专项文档。
- 二进制下载接口直接返回文件流，不使用 JSON 信封。

### 2.3 状态码

| HTTP | 客户端行为 |
|---|---|
| 200 / 201 / 204 | 成功（204 仅用于无返回体的上传） |
| 401 | 判定密钥失效，保留最近一次有效配置缓存，提示重新授权 |
| 403 | 提示无权限，不重试 |
| 404 | 资源/备份不存在；资源列表按空处理，备份提示“云端还没有备份” |
| 413 | 提示文件过大 |
| 429 | 退避重试或提示稍后再试 |
| 5xx | 指数退避，保留当前配置/缓存 |

### 2.4 安全限制

- 客户端拒绝跨源下载地址，只接受与 Base URL 同源（同 scheme/host/port）的地址。
- 客户端不跟随重定向；云端不要用 302 跳转到对象存储，直接返回同源地址或让客户端走标准下载路由。
- 不要把对话正文、日记正文、api-key 写进服务端普通访问日志。
- 资源与备份都按账号隔离，不能只靠列表隐藏，下载时还要再次校验权限。

## 3. 接口总表

| 功能 | 方法 | 路径 | 是否新增 |
|---|---|---|---|
| 拉取配置 | POST | `/api/v1/getconfig` | 既有 |
| 皮肤列表 | GET | `/api/v1/skins` | 既有 |
| 皮肤下载 | GET | `/api/v1/skins/download/{id}` | 既有（或使用 `download_url`） |
| 音色列表 | GET | `/api/v1/mimo/voices` | 既有 |
| MMD 列表 | GET | `/api/v1/mmd/projects` | 既有 |
| MMD 下载 | GET | `/api/v1/mmd/projects/{id}/download` | 既有（或使用 `download_url`） |

计费接口由配置里的 `billing.*` / `pricing.*` 下发，客户端按配置调用，不在本表硬编码。

## 4. 配置下发

### 4.1 请求

```http
POST /api/v1/getconfig
Authorization: Bearer <api-key>
Content-Type: application/json
```

请求体包含：

```json
{
  "mod_version": "4.4",
  "client_id": "...",
  "billing_protocol_version": 2
}
```

### 4.2 响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "version": 12,
    "config_id": "cfg_xxx",
    "overrides": {
      "hud.dialogueHud": true,
      "hud.dialogueSeconds": 20
    }
  }
}
```

硬性要求：

- `data.version` 必须是 `>= 0` 的整数，每次改动递增。
- 版本比客户端已应用的版本小，整份配置会被忽略，防止回滚。
- `data.overrides` 可选；键名使用 TOML 点分路径，最多 512 个键。
- `cloud.*` 段禁止通过 `overrides` 下发；`webSearch*` 由本机管理，云端下发会被忽略。
- 目前 180 项配置全部支持 `overrides`，不需要为每个配置项单独加字段。
- 云端白名单可直接使用 `docs/modConfigKeys-180.js`；4.4 相对 4.3 的实际差异是
  **新增 12 项、移除 2 项**（含 4.3 漏收录的 `plugin.*` 3 项和已删除的 `tts_audio_sink` 段），
  详见 `docs/配置键白名单-4.4.md`。

详细规则、具名字段清单和保存守卫见：

`docs/Mod配置云端下发适配文档.md`

## 5. 资源中心

### 5.1 皮肤

```http
GET /api/v1/skins
```

```json
{
  "code": 0,
  "data": {
    "skins": [
      {
        "name": "skin_id",
        "display_name": "显示名",
        "download_url": "/api/v1/skins/download/skin_id",
        "file_size": 123456,
        "is_owner": 0,
        "is_public": 1,
        "is_global": 0
      }
    ]
  }
}
```

- `download_url` 可省略；省略时客户端请求 `GET /api/v1/skins/download/{name}`。
- 客户端下载上限 32 MiB，解压后总大小上限 64 MiB，最多 64 个条目。
- 皮肤 ZIP 必须包含约定的 16 张表情纹理。

### 5.2 MiMo 音色

```http
GET /api/v1/mimo/voices
```

```json
{
  "code": 0,
  "data": {
    "voices": [
      { "id": "Dean", "name": "Dean", "type": "builtin" },
      { "id": "custom_1", "name": "自定义", "type": "clone" }
    ]
  }
}
```

- 音色由云端按 ID 直接使用，**没有本地下载步骤**。
- `type` 为 `builtin` 或 `clone`；客户端据此显示“平台内置”/“云端克隆”。
- 列表接口 404 时，资源中心音色页按空处理，不影响皮肤和 MMD。

### 5.3 MMD

```http
GET /api/v1/mmd/projects
```

```json
{
  "code": 0,
  "data": {
    "projects": [
      {
        "id": "senbonzakura",
        "name": "千本樱",
        "type": "mmd",
        "format": "zip",
        "version": 1,
        "file_size": 8451276,
        "sha256": "0123456789abcdef...",
        "download_url": "/api/v1/mmd/projects/senbonzakura/download",
        "is_public": 1,
        "is_owner": 0,
        "is_global": 0
      }
    ]
  }
}
```

- `download_url` 可省略；省略时客户端请求 `GET /api/v1/mmd/projects/{id}/download`。
- 下载上限 256 MiB，最多 128 个文件，单文件解压后上限 192 MiB。
- 客户端会校验 ZIP 路径穿越、扩展名、`manifest.json`、VMD 动作轨；`sha256` 存在时必须匹配。
- 列表 404 时 MMD 页按空处理，不影响其它资源。

详细校验与上传审核要求见：

`docs/MMD资源中心云端适配文档.md`

## 6. 对话/日记备份（新增）

### 6.1 设计原则

- **只有玩家主动点击“上传当前记录”才上传**，不做后台自动同步。
- 上传内容是当前存档的全部对话与日记，格式与本地导出 JSON 完全一致。
- 恢复按时间去重合并，不覆盖本地已有记录。
- 建议云端按账号隔离，并支持删除备份。

### 6.2 上传

```http
POST /api/v1/user/data/backup
Authorization: Bearer <api-key>
Content-Type: application/json; charset=utf-8
```

请求体：

```json
{
  "format": "verity_extended.export",
  "version": 1,
  "exportedAt": 1730000000000,
  "world": "MyWorld",
  "conversations": [
    { "t": 1730000000000, "w": "MyWorld", "u": "玩家说的话", "a": "Verity 的回复" }
  ],
  "diaries": [
    { "t": 1730000000000, "w": "MyWorld", "d": "日记正文" }
  ]
}
```

成功响应：

```json
{
  "code": 0,
  "message": "",
  "data": { "id": "backup-id", "updated_at": 1730000000000 }
}
```

也接受 `HTTP 204` 无返回体。

### 6.3 恢复最近备份

```http
GET /api/v1/user/data/backup/latest
Authorization: Bearer <api-key>
```

成功响应支持以下三种形态，客户端自动识别：

```json
{ "code": 0, "data": { "updated_at": 1730000000000, "backup": { "format": "verity_extended.export", "...": "..." } } }
```

```json
{ "code": 0, "data": { "updated_at": 1730000000000, "json": "{\"format\":\"verity_extended.export\",...}" } }
```

```json
{ "code": 0, "data": { "format": "verity_extended.export", "conversations": [], "diaries": [] } }
```

没有任何备份时返回 `404`，客户端提示“云端还没有备份”。

### 6.4 去重与大小

- 对话重复判定：`t + u + a` 相同。
- 日记重复判定：`t + d` 相同。
- 重复恢复同一份备份结果稳定，不会翻倍。
- 建议单次备份上限 8 MiB；当前客户端不压缩，直接上传 UTF-8 JSON。
- 建议每个账号保留最近 10 份，或只保留最新一份并覆盖。

### 6.5 隐私

- 对话和日记属于隐私数据，不要写进普通日志。
- **`payload` 必须做应用层列级加密**：AES-256-GCM，按行随机 nonce，密钥放环境变量/KMS，
  另存 `key_version` 以支持轮换；旧明文行可用 `enc:` 前缀规则兼容。
- 基础设施层仍应开启磁盘/备份加密与最小权限；列级加密是补充，不替代访问控制。
- 提供“删除云端备份”的账号入口。
- 未授权账号不得创建或读取备份。
- 当前客户端没有端到端加密，依赖 HTTPS 与服务端访问控制；列级加密是服务端静态加密，
  服务进程仍能解密，不等同于端到端。

### 6.6 限流

备份接口按账号限流（鉴权通过后才计数）：

| 接口 | 限制 |
|---|---|
| `POST /api/v1/user/data/backup` | 6 次/分钟/账号 |
| `GET /api/v1/user/data/backup/latest` | 30 次/分钟/账号 |
| `DELETE /api/v1/user/data/backup` | 10 次/分钟/账号 |

- 超限返回 HTTP `429`，响应体保持 `code/message/data` 信封，并带 `Retry-After` 头。
- 单实例可用内存滑动窗口；多实例部署时用共享存储（Redis/DB）计数。
- 客户端只会手动触发这些操作，正常使用不会触限；限流目的是防止脚本滥用 8 MiB 上传。

完整契约与测试清单见：

`docs/对话记录云端同步适配文档.md`

## 7. 计费与用量

计费协议沿用既有实现：

- `data.billing` / `data.pricing` 下发计费模式、预留/结算地址和单价。
- 付费线路先预留，再按真实 usage 结算；失败会进入本地待处理队列重试。
- 本总览不新增计费接口；云端不要因为新增备份接口而改动既有计费路径。

## 8. 上线顺序建议

1. **配置下发**：先保证 `getconfig` 的 `version`、`config_id`、`overrides` 正确。
2. **资源列表**：`skins` / `mimo/voices` / `mmd/projects` 三个 GET 先上线，下载可后补。
3. **资源下载**：按同源地址返回，校验权限、大小和 SHA-256。
4. **对话/日记备份**：先实现上传和最近备份读取，再做删除与多版本。
5. **计费**：保持现状，最后联调。

## 9. 联调检查清单

- [ ] 未授权请求返回 401，客户端提示重新授权且不清空本地缓存。
- [ ] `getconfig` 的 `version` 递增、回滚版本被忽略。
- [ ] `overrides` 里不出现 `cloud.*`；`webSearch*` 下发被忽略。
- [ ] 三个资源列表在 404 时按空处理，不阻塞其它页。
- [ ] 皮肤/MMD 下载为同源地址，不跟随跨源重定向。
- [ ] 备份空账号返回 404，上传成功后 `latest` 能取回同一份 JSON。
- [ ] 同一份备份恢复两次，第二次新增 0 条。
- [ ] `payload` 已列级加密，dump/备份中无明文正文；`latest` 解密回读与上传一致。
- [ ] 备份接口按账号限流（POST 6/min、latest 30/min、DELETE 10/min），超限 `429` 带 `Retry-After`。
- [ ] 401/413/429/5xx 都有可读提示，且不破坏本地数据。
- [ ] 对话正文不进入服务端普通日志。
