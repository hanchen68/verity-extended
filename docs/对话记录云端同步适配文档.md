# 对话记录 / 日记云端同步适配文档

> 适用扩展版本：4.4+
> 客户端类：`cloud/CloudBackupClient`、`client/VerityCloudBackupScreen`
> 鉴权：沿用云端配置的 `Authorization: Bearer <api-key>`
> 传输：HTTPS（本机回环可用 HTTP），JSON，UTF-8

## 1. 设计约束

- **只有玩家主动点击「上传当前记录」才会上传**，不做后台自动同步。
- 上传内容是当前存档的全部对话与日记，格式与本地导出 JSON 完全一致。
- 恢复按「时间 + 玩家 + 回复」/「时间 + 正文」去重合并，不覆盖本地已有记录。
- 云端应按账号隔离；支持删除备份；建议单次备份上限 8 MiB（客户端未压缩）。

## 2. 上传

```http
POST /api/v1/user/data/backup
Authorization: Bearer <api-key>
Content-Type: application/json; charset=utf-8
Accept: application/json
```

请求体：

```json
{
  "format": "verity_extended.export",
  "version": 1,
  "exportedAt": 1730000000000,
  "world": "MyWorld",
  "conversations": [
    { "t": 1730000000000, "w": "MyWorld", "u": "玩家说的话", "a": "Verity 的回复" }
  ],
  "diaries": [
    { "t": 1730000000000, "w": "MyWorld", "d": "日记正文" }
  ]
}
```

成功响应（HTTP 200/201 均可）：

```json
{
  "code": 0,
  "message": "",
  "data": { "id": "backup-id", "updated_at": 1730000000000 }
}
```

- `data.updated_at` 可选，用于界面显示；缺失时客户端按 0 处理。
- 建议云端保留每个账号最近 N 份（例如 10 份），或只保留最新一份并覆盖。

## 3. 恢复最近备份

```http
GET /api/v1/user/data/backup/latest
Authorization: Bearer <api-key>
Accept: application/json
```

成功响应支持以下三种 `data` 形态，客户端会自动识别：

```json
{ "code": 0, "data": { "updated_at": 1730000000000, "backup": { "format": "verity_extended.export", "...": "..." } } }
```

```json
{ "code": 0, "data": { "updated_at": 1730000000000, "json": "{\"format\":\"verity_extended.export\",...}" } }
```

```json
{ "code": 0, "data": { "format": "verity_extended.export", "conversations": [], "diaries": [] } }
```

- 没有任何备份时返回 `404`，客户端提示“云端还没有备份”。
- 返回的 JSON 必须是本扩展的导出格式；格式不正确时客户端提示“无法识别的备份格式”。

## 4. 状态码约定

| HTTP | 客户端提示 |
|---|---|
| 401 | API Key 无效，请重新同步云端配置 |
| 403 | 当前账号无权备份 |
| 404 | 云端还没有备份 |
| 413 | 备份文件过大 |
| 429 | 上传过于频繁，请稍后重试 |
| 5xx | 云端暂不可用 |

## 5. 合并与去重

- 对话：`t + u + a` 三元组相同视为重复。
- 日记：`t + d` 相同视为重复。
- 恢复不会删除本地记录，只追加缺失项；重复恢复同一份备份结果稳定。

## 6. 隐私要求

- `payload` 必须做应用层列级加密（AES-256-GCM，按行随机 nonce，密钥放环境变量/KMS，
  另存 `key_version` 以支持轮换）；磁盘/备份加密与最小权限作为基础设施层补充。
- 不要写入日志正文。
- 提供“删除云端备份”入口。
- 不要为未授权账号创建备份。
- 当前客户端未做端到端加密，依赖 HTTPS 与服务端访问控制；列级加密是服务端静态加密，
  服务进程仍可解密，不等同于端到端。

## 7. 后端上线检查清单

- [x] `POST /api/v1/user/data/backup` 可用，校验 Bearer 与账号。
- [x] `GET /api/v1/user/data/backup/latest` 可用，无备份返回 404。
- [x] 响应保持 `code/message/data` 信封。
- [x] 单账号隔离；不要跨账号读取。
- [x] 限制请求体大小并返回 413。
- [x] 不把对话正文写入服务端普通日志。
- [x] `payload` 列级 AES-256-GCM 加密上线，表带 `key_version`；dump/备份中无明文正文。
- [x] 错误密钥/缺失密钥时返回 500 且响应与日志不出现明文；加密后 `latest` 解密回读与上传内容逐字节一致。
- [ ] 按账号限流：`POST /backup` 6 次/分钟，`GET /backup/latest` 30 次/分钟，
      `DELETE /backup` 10 次/分钟；超限返回 `429` 并带 `Retry-After`。

## 8. 限流

限流在 Bearer 鉴权通过后按**账号**计数；未授权请求直接 `401`，不进入限流。

| 接口 | 限制 |
|---|---|
| `POST /api/v1/user/data/backup` | 6 次/分钟/账号 |
| `GET /api/v1/user/data/backup/latest` | 30 次/分钟/账号 |
| `DELETE /api/v1/user/data/backup` | 10 次/分钟/账号 |

- 超限返回 `429`，响应体使用 `code/message/data` 信封，同时带 HTTP `Retry-After` 头（秒）。
- 鉴权后的请求都计数（含参数校验失败），避免脚本反复打满 8 MiB 上传。
- 单实例可用内存滑动窗口；如果部署多实例，需要改用共享存储（Redis/DB）计数。
- 客户端这些操作都是玩家手动触发，正常使用不会触限。
